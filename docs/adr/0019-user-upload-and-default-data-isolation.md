# 用户上传视频与默认数据隔离：新用户只见自己的视频，整库须显式授权

2026-11-15 用户 grilling 确认（首期范围只做水迷宫）。平台要支持自助注册的独立研究者，因此引入「用户上传」，并把默认数据可见范围收紧到用户自己的数据。本决策**部分废止 ADR-0008**「登录用户全库只读」。

## 决策

### A. 用户上传视频

- 视频只能在项目内上传：先建项目，再在项目里上传；不允许上传后不挂项目。
- 上传的视频是一种「视频来源」（见 GLOSSARY「用户上传」），存放在平台服务器，所有权归上传者。
- 单文件上限 2GB，格式只收 mp4 与 avi。这是本期产品上限，调整需另作决策。
- 项目只持有归组关系，上传文件的所有权归用户，与 ADR-0016「成员是引用」一致；项目仍只属于单个用户。
- 文件存储落在平台侧，不交给推理服务，也不只留在浏览器。

### B. 默认数据隔离

- 新注册用户默认只能访问自己上传的视频，以及这些视频在自己项目中的推理与分析结果。
- 现有水迷宫整库（当前约 549 条试次）仅管理员与被管理员明确授权的账号可见。
- 首期不做项目成员分享。

## 与 ADR-0008 的关系

ADR-0008 针对当时的 Text-to-SQL 问答面，在「单课题组、无外部多租户压力」的假设下接受「登录即可查全库」，并明确写明引入外部用户前须反转。自助注册的独立研究者正是该触发条件，故全库只读不再适用，由本 ADR 取代。

试次浏览面「普通用户仅见被授权实验、管理员可见全部」与本决策方向一致；变化在于默认可见范围改为「自己上传的视频」，整库须显式授权。ADR-0008 的库层防线描述属历史记录（问答面已按 ADR-0014 退役），不在此改写。

## 考虑过的方案

- **继续「登录即可查整库」（ADR-0008）**：新用户会看到他人或课题组的数据。否决。
- **新用户只读整库、分析结果只写入自己的项目**：仍会暴露他人视频。否决。
- **上传后可以不挂项目**：与「项目是组织单元」不一致，后续推理与发布没有归属。否决。
- **首期做项目成员分享**：与 ADR-0016「首期个人使用、项目属单用户」冲突，本期不做。
- **把上传文件存进推理服务，或只放在浏览器**：前者破坏「推理服务不持有平台数据所有权」，后者换设备即丢失。否决。

## 后果

- 平台网关、存储、工作区自动开通，推理结果的可见性，以及科研 Agent 的数据范围，都要按本决策调整；本 ADR 不规定实现，由后端工单拆解。
- 自助注册用户开通个人科研工作区，不再停留在无工作区状态。
- 试次列表中看似可点、实际无法打开的旧详情入口（旧试次详情已按 ADR-0014 下线）应在前端移除或改为说明。
- 项目不增加实验者、日期、物种、范式字段；元数据仍属于「实验」。
- 推理任务上的逐帧复核与「发布」流程（ADR-0017）不变。
- 本期不引入通用行为谱或自定义个体管理。
