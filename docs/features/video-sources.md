# 项目视频来源与文件夹（NAS 首期）

2026-11-12 用户确认：进入项目先选择视频文件夹；视频来源可扩展，首期以 NAS 为主，阿里云盘、百度网盘以后接入。用户已确认以项目页面和服务端目录接口两个公开接口做 TDD 验收，并授权 Agent 自行完成后续设计、实现和收尾。

## 首期行为

1. 项目页先展示来源与目录选择；默认可选择现有推理视频目录。已有项目保留原有科研任务、视频引用和已发布结果。
2. 用户浏览来源内目录，保存当前文件夹。每个项目保存一个 `source_id + path + label` 引用，属于登录账户，刷新后保留。保存先核验项目所有权与推理端可读性；失败不覆盖已保存目录。
3. 文件夹内 MP4 可由用户选择归入项目；不自动递归导入，不自动启动 GPU，不代替研究者确认预标注或复核追踪。移出引用不删除视频。
4. 视频来源由推理端集中管理。首期提供 filesystem adapter，NAS 通过推理机器可读的预挂载目录配置；来源绝对路径、凭据及未来网盘下载地址不返回浏览器。
5. 保持默认来源旧视频 ID、历史任务与推理算法兼容。新增来源使用带来源身份的视频 ID；平台不解码。项目须完整保存并可移出最长 4096 字符的视频引用，不以截断满足数据库索引。
6. 未知来源、目录越界拒绝；来源断开、无权限与空目录有明确区别；required_mount 指定的挂载消失后不得误读挂载点下的本地空目录。浏览/保存期间切换来源或项目不能显示旧请求结果。
7. NAS 尚未连接时如实提示，不以已连接标签代替实际连通。阿里云盘与百度网盘本期没有授权、下载或上传实现，不展示虚假的可用入口。

## 契约

- 推理 `GET /v1/sources` → `{items:[{id,label,kind:"filesystem",available,error?}]}`；不含服务器路径。
- 推理 `GET /v1/videos?source_id=legacy&path=` → `{source_id,path,items}`；`items` 沿用目录 `type/name/path` 与视频 `type/name/id`。默认来源 ID 为 `legacy`。
- 平台通过认证推理网关转发上述读取，仅放行 `source_id` 与 `path`，不接受任意 URL。
- 平台 `PUT /api/v1/projects/{project_id}/video-folder`，请求 `{source_id,path}`，响应 `ProjectPublic`；新增 `video_folder:{source_id,path,label}|null`。
- NAS 在私有运行配置中登记来源 ID、显示名、挂载根目录和可选必需挂载点；同名文件在不同来源的身份不能碰撞。

## 验收与边界

- 项目页浏览、保存、刷新后保留、视频归入和移出；来源不可用/保存失败/竞态有可理解提示，账户缓存隔离。
- 目录接口认证、遍历防护、符号链接越界、不可用挂载、不同来源身份、旧 ID 兼容，以及创建任务后 worker 解析到相同实际视频。
- 平台长 ID 的真实 MySQL 持久化、幂等与删除，以及旧成员迁移保留。
- 实际 NAS 发现和连通事实另记部署验收；合成目录测试不作为真实 NAS 接入证据。现有 #45 研究者亲自确认/复核的真实视频闭环继续开放。
