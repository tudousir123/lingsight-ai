# ADR-0018：项目分析任务的范围与跨版本门禁

状态：已实现，2026-11-11。

项目页的“分析本项目数据”进入独立任务输入页；创建时传 project_id。网关先检查个人工作区许可、请求体大小及当前用户对项目的归属，再向 Agent 的鉴权 /v1/capabilities 探测 immutable-v1 能力和项目源配置。能力缺失、旧版本、未配置、探测异常或无效响应一律 503，且不发送创建任务的 POST。不能只在浏览器事后检查：旧 Agent 会忽略新字段并已经开始无范围任务。

网关沿用同一个转发内核和服务级凭据。内核提供有界请求体读取与显式字节载荷，避免校验后重复消费流或绕过大小上限；能力响应限制为 4096 字节。未指定项目的既有任务不访问项目数据表或能力端点。

独立 Agent 在创建时固化 project_id。消息、取消、澄清、恢复不改范围；查询只走专用应用库只读源和固定结构化选择，不回退旧 v3。具体实现及权限模板在独立 Agent 仓 ADR-0005。

前端检查创建响应范围；异常时尝试停止新 Run，保留原问题，明确显示不能确认停止的情况。正常创建后幂等加入项目列表；归组失败只提示重新整理，不重建任务。刷新从 Agent task.project_id 重建范围提示。项目不可用时不退回无项目分析。

部署必须先更新 Agent 并配置新的最小权限 DBHub 源，再上线平台。capabilities 只证明服务代码和配置存在；真实数据连通、GPU 推理人工复核、正式容器迁移与用户科研结论验收必须另行留证。平台旧版与 Agent 新版可共存；平台新版遇 Agent 旧版只能继续无项目旧任务，不能启动项目任务。

验证：旧代码的六个不兼容服务场景已复现失败；修复后项目范围与网关契约全绿。另以真实 FastAPI → Node → 临时 SQLite 验证项目创建、范围持久化、后续消息及 ZIP manifest；数据库均为独立临时 MySQL，未访问真实科研库或模型。
