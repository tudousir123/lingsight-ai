# 并行开发与后端收口复盘（2026-11-10）

范围：平台工作区、独立 Agent 仓库及本轮验收；证据在同目录测试日志和独立仓库 `docs/evidence/backend-readiness/`。

1. **数据出站边界缺口。** 合成行验收曾把真实科研库的表/列和科研 Skill 发给云端模型。已将模型会话改为默认拒绝，必须明确开启数据传输授权；合成验收改用虚构提示、Skill、表列和不含科研模块的独立镜像。还需要逐任务或逐数据源的细粒度授权时，应先定义产品接口；全局开关不能代表逐视频授权。
2. **并行工作混在同一个工作区。** 主站前端、产品文档和后端同时未提交，很难辨认基线。此次依据改造前快照建立单独的后端 worktree，保留原工作区；后续多工单继续按 `docs/agents/parallel-tickets.md` 隔离分支和 worktree，在集成前明确每个提交的归属。
3. **并行测试覆盖率互相覆盖。** 隔离 MySQL 并不能隔离同一个 `.coverage` 文件；两个测试同时运行曾得到错误的覆盖率。`scripts/test-local.sh` 改为每次独立 coverage 文件并串行发布公共 HTML；双 runner 已验证。共享数据库的互斥锁也改为由 MySQL 按库持有，不受连接 URL 别名影响。
4. **缺少独立 Agent 的自动检查。** 新增 GitHub Actions，运行类型检查及真实容器测试，覆盖生命周期和隔离边界；此处只证明工作流已配置，远端结果以实际运行记录为准。
5. **旧环境与验收环境边界不清。** 主站本机开发栈已有持久数据库，原 Playwright 脚本会清理核对记录；本轮新增的浏览器验收使用临时 MySQL、临时 Agent、虚构 MCP 和复制的 Vite 源码，不触碰现有业务库和前端工作区。
