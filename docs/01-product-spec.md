## 2026-11-15：个人 Agent 首版的持久身份纵向切片（#75 / #76）

个人 Agent 身份、持久环境、Task、Run 和 Pi Session 是不同概念。独立 Agent 根据平台网关注入的当前用户 UUID 保存唯一的个人身份与环境身份；平台不复制其业务持久化。新任务绑定服务端身份，任务上下文、输入与产物仍分别归属 Task/Run，不把跨任务持久性实现为无限续接会话。未核验的历史任务不自动认领或迁移。

工作区通过现有认证网关读取 `GET /api/v1/agent/personal-agent`，展示身份及环境可用状态。网关核验 `personal_agent=persistent-v1`、`environment=task-workspace-v1` 后才开放该入口和新任务创建；旧服务、环境不可用或任务未绑定当前环境时，页面禁用新增执行但保留输入、材料查看与停止入口。账号、项目不可变范围、实时授权和出站同意保持有效。

环境采用服务专属私有目录和每任务/执行目录；接口仅返回逻辑契约，不接受宿主路径、shell 或客户端身份选择。Python 沿用输入只读、输出限当前执行的受控容器，不向工具共享整个人环境或其他任务目录。身份、明确输入和已完成输出落盘后可跨服务重启保存，临时进程无需永久存活。

本切片仅在临时合成环境验证，不代表现役服务升级。真实 Durable、受控浏览器、记忆及故障恢复完整矩阵由后续票实现，不由本身份能力标识暗示已具备。

## 2026-11-15：个人偏好权威与派生索引切片（#75 / #82）

工作区通过独立 Agent 的 `personal-memory-v1` 能力查看当前用户自动保存的稳定表达偏好、内容版本、来源任务/版本/哈希，以及已提供给当前任务执行引擎的记忆依据。个人偏好允许本人跨项目复用，不扩大数据库或工具授权；单次要求、科研结论、统计口径、阈值及样本规则保守不提升。当前自动接纳使用有界中英文稳定表达形式且要求抽取结果为原文，不能称为任意语言或表达的通用分类器。

独立 Agent SQLite 保存权威内容、归属、版本、来源与来源去重；官方 Python Mem0 OSS `mem0ai==2.2.1` 及本地嵌入式 Qdrant 向量库仅为派生索引。服务端按用户生成物理分区，抽取前历史检索也仅从该用户的有效权威记录重建；不是只在最终 search 添加 metadata 过滤。索引故障保留权威可查，界面明确提示召回不可保证，不编造缓存成功状态。后续科研候选确认和更正/删除由 #83/#84 实现，不由本票自动确认。

记忆抽取、embedding 使用分别显式配置且获授权的处理端点；未配置时不调用默认云服务，也不读取个人工具凭据。界面展示接收方；重排和遥测关闭。处理器结果在库解析/embedding 前受数量、原文、深度、字节和累计请求预算约束；子处理器仅在独立 OS 内存/CPU/进程限制下运行，不支持时禁用记忆配置，普通任务仍可运行。正常任务模型仍受既有独立出站门禁约束。真实 Mem0 + 合成本地模型/embedding 端点的 API、跨仓网关和工作区验证只证明工程契约/隔离；**真实语义质量评测仍未验收，需获授权配置及费用范围**，已与真实 Durable/Harness 完成本地合成协议联验；最终候选安全复核仍待完成。本切片不授权现役升级、迁移、部署或真实科研数据出站。

### 产品目标及首期范围

用户指定已有实验数据与研究问题，Agent 自主查数据、编写并运行分析、修正图表、形成附有统计口径和来源的可编辑报告。工作区围绕科研任务保存对话、代码、数据依据及交付物，支持继续修改；常规步骤自动执行，关键科研口径不清时提问。首期仅个人使用，在本机运行。

首期接入水迷宫现有 v3 数据与经核对的本地资料，不把上传视频后自动 GPU 推理、论文 RAG、自动论文结论、PDF/Word 排版或多课题组隔离列为本次闭环验收内容。已有实验浏览保留，独立的 SQL 生成/修复问答管线在替代闭环验收后退出。

### 两个仓库、三个运行职责

| 归属 | 职责 | 首期建议 |
|---|---|---|
| `lingsight-ai` 平台 | React 科研任务工作区、用户入口、实验浏览；FastAPI 对接 Agent API | 沿用现有 React/FastAPI 基座；任务内容由 Agent 服务提供 |
| 独立 [`lingsight-agent`](https://github.com/tudousir123/lingsight-agent) 仓库 | 任务 API、状态和步骤事件、Pi 会话、MCP 数据访问、分析执行协调、交付物 | TypeScript/Node.js 服务，内部集成 Pi SDK；独立启动和版本化 API |
| 独立分析执行环境 | 运行 Agent 编写的 Python 和确定性科研函数，生成图表及报告材料 | 本机按执行启动 Python 容器；只获得明确输入与输出目录，记录镜像和依赖版本 |

Agent 服务自己拥有任务与产物，不依赖平台应用库才能运行；其他客户端可通过相同 API 使用它。FastAPI 可作为网页调用的网关，沿用平台登录入口；服务本身使用独立的本地访问凭据，避免把个人 Pi 全局配置当成应用的隐式依赖。公开网络入口和多租户鉴权另行设计。

### Pi SDK 的职责

Pi 负责模型会话、上下文、工具循环、修正代码、用户补充要求及流式事件。服务通过自己的适配层注册科研工具与 Skills、关联 Pi 会话和科研任务，并把内部事件转换为稳定的任务协议。调研依据本机 SDK 1.2.0；首期实现锁定 `@earendil-works/pi-coding-agent@1.5.0` 及 npm lockfile，升级后复核类型与行为，不依赖滚动 `latest`。

首期以服务自有 MCP 适配器连接 DBHub，并注册为受控 Pi 科研工具，以便在本地保存大结果及来源；不默认加载 CLI MCP 扩展或个人配置。Pi 持久会话不等于完整任务状态或任意 Python 进程的可恢复执行；一次模型回复结束也不等于报告已通过验收。服务应显式配置自己的资源、模型通道和工具，不默认载入所有个人扩展。

### 数据流：大结果进入文件，模型看到引用及摘要

1. 用户给出问题与数据范围，服务创建任务并记录数据引用及分析要求。
2. Agent 通过 DBHub 的元数据工具识别可用表和维度，按需引用本地 registry 和科研 Skills。
3. 小结果可直接用于探索。帧级、RLE 等大结果由数据工具通过 DBHub 获取并落为任务的数据快照；返回文件引用、列、行数、时间范围和哈希，避免把整库或长 RLE 堆进模型上下文。
4. Python 执行环境读取明确的数据快照与分析代码，产出表格及图形；常用指标优先复用已核对的确定性函数。
5. Agent 检查执行错误、数据条件、产物和口径，必要时修正代码或提出澄清，再生成报告及材料清单。

数据快照保存 SQL/参数或数据选择依据、source ID、查询时间范围、实际文件哈希和 registry 引用。跨多次查询不宣称数据库原子快照；需要一致版本时应在数据工具实现中明确验证。数据库工具保留只读职责，平台不恢复原有专用 Text-to-SQL 编排；资源上限、超时和错误处理属于数据连接器契约。

### v3 的领域条件与科研 Skills

v3 当前是帧级结果与几何参考库，没有现成的独立动物、分组、试次维度和 `trial_metrics` 表。沿用旧 SQL/YAML schema 不成立。现有 registry 与历史解析器保留为有来源和核验状态的映射候选，不能自动升级为已确认动物登记表。

科研 Skills 记录适用数据版本、指标定义、有效帧条件、分组和聚合规则、报告要求，以及可调用的确定性函数。既有 7px 朝向算法按所属项目规定冻结；调用经过确认的实现，而不是让模型随任务改写核心定义。

- 未核验映射时允许视频级轨迹、朝向及探索性图表，报告明确标注身份状态。
- 动物数、逐鼠汇总及正式组间结论必须有已确认映射；不同年龄批次默认分开。
- 缺少空间标定不输出厘米单位；数据质量字段含义和缺失值处理需有可追溯定义。
- 没有足够依据的指标明确不可计算或有待核验，不用示例值、零值或任意插补替代。

### 任务、执行与产物模型（工程建议）

- **Task**：持续的科研问题工作空间，拥有目标、数据范围、讨论、已确认口径及交付物。
- **Run**：任务中的一次执行尝试；一个任务可以在修改分析要求后产生新 Run。等待澄清后继续同一次 Run。
- **Step/Event**：执行步骤及可重放事件，用于进度展示、错误定位、澄清和恢复。
- **Artifact**：数据快照、代码、图表或报告的有版本文件，绑定产生它的执行及输入来源。
- **Clarification**：需要用户确认的科研口径或数据条件，保存问题、回答及所影响的步骤。

Task ID 不等于实验 ID、Trial ID 或 Pi Session ID。首期建议任务元数据及事件使用 Agent 自有 SQLite，完整文件位于服务数据目录，Pi JSONL 仅保存引擎会话；这些都是运行数据，不提交 Git。数据库 schema 和确切目录在实现时确定。

### 后台运行、恢复与用户介入（工程建议）

Run 状态：`queued → running → waiting_for_input / succeeded / failed / cancelled / interrupted`。`waiting_for_input` 收到答复后回到 `running`；`interrupted` 在验证恢复依据后重新进入队列。最终 `succeeded` 需有通过检查的交付清单，不由单个 Pi 事件直接判定。

- 首期一个分析执行占用一个计算槽，其余任务排队；状态和预算均可配置，初期无需独立 Redis/Celery 集群。
- 关闭浏览器只断开订阅，不取消任务。重新打开按事件 ID 获取遗漏进度。
- 正常取消通知 Pi 中止，并终止该 Run 的分析执行；已完整生成的产物保留，未完成产物不标作成功。
- 服务启动时扫描中断 Run。已完成的数据快照与产物经哈希/清单验证后复用；未完成步骤从边界重跑，不声称恢复任意 Python 内存状态。
- 已经明确的口径沿用，普通查询和代码修正连续执行；关键口径不明则持久保存澄清并等待答复。
- 用户修改目标时保存新的需求与代码/报告版本。运行中的补充要求以明确的调整或后续执行语义交给 Pi，避免静默丢弃或覆写。

### 独立 API 契约草案（建议 `/v1`）

| 接口 | 用途 |
|---|---|
| `POST /v1/tasks` | 创建任务与首个执行，返回 Task/Run ID |
| `GET /v1/tasks`、`GET /v1/tasks/{id}` | 列表与任务快照 |
| `POST /v1/tasks/{id}/messages` | 补充要求；明确调整当前执行或排入后续执行 |
| `GET /v1/tasks/{id}/events` | SSE；支持按事件 ID 从已保存进度继续读取 |
| `GET /v1/runs/{id}` | 获取一次执行状态、步骤与预算信息 |
| `POST /v1/runs/{id}/clarifications/{question_id}/answer` | 回答口径问题并继续执行 |
| `POST /v1/runs/{id}/cancel`、`POST /v1/runs/{id}/resume` | 取消或从已验证边界继续 |
| `GET /v1/artifacts/{id}` | 获取已登记交付物；不把任意宿主路径作为下载接口 |
| `GET /v1/tasks/{id}/bundle` | 下载报告、图表、CSV、代码和来源清单 |

提交类接口返回接受状态及资源 ID；执行不绑定到单个长 HTTP 请求。两个仓库对 Task、Run、事件和 Artifact 结构约定版本，兼容性测试由双方保留。草案未承诺具体 Web 框架或数据库字段实现。

### 交付物与最小验收

每个成功任务至少交付 Markdown 报告及网页预览、PNG/SVG 图表、CSV 明细、Python 分析代码、依赖信息和来源清单。报告写明数据范围、映射核验状态、单位、纳入/排除条件、聚合口径与不能支持的结论。

首期真实验收从一个有可用 v3 帧/几何数据的视频任务开始，不以未核验的逐鼠统计作为完成前提。需要验证：

1. Agent 经 DBHub 获取真实输入，执行 Python，交付可预览和下载的图表及报告，代码和文件有来源记录。
2. 用户在同一任务修改图表要求，保留原版本，并产生可回查的新版本。
3. 关闭网页任务继续；重连能读取事件。服务中断后明确恢复点，已完成步骤不凭空重算或冒充成功。
4. 数据不可用、代码失败、口径待确认、取消和恢复均有明确状态；错误或空结果不编造成科研结论。
5. 小型确定性夹具验证核心指标和输入契约；实际科学计算优先使用冻结/已确认实现。新服务使用隔离夹具与显式真实视频 smoke 验收；不运行会清空既有开发账号的旧项目 pytest。

### 实施顺序与旧系统迁移

A. 新建独立 Agent 仓库：服务接口、SQLite/文件持久化、Pi 适配与任务事件；先以确定性夹具验证。

B. 接入本地 DBHub、版本化科研 Skills 和独立 Python 执行；打通一个真实视频级分析到报告及完整下载。

C. 接入后台运行、澄清和中断恢复，完成故障与重连验收；随后联调 LingSight 的任务工作区和 API 网关。

D. 新闭环验收后退出旧 `/qa` 页面及独立 SQL 生成/修复管线。登录、实验浏览和原有核对能力保留；其中旧科研库接口迁往 v3 时需单独核对数据契约，不能直接切换数据库名字。旧库和实验原始数据不因前端迁移而删除。

用户已确认进入最小闭环实现。独立私有仓库为 [lingsight-agent](https://github.com/tudousir123/lingsight-agent)，服务、持久化、轻量任务客户端及独立 Python 执行均在该仓库；具体版本与实测结果以其[验收记录](https://github.com/tudousir123/lingsight-agent/blob/main/docs/mvp-verification.md)为准：Pi SDK 1.5.0、用户配置的 GLM-5.3、DBHub 只读快照、独立 Python 容器、可编辑报告及完整材料。9 项含真实容器的行为测试通过；首个真实图表曾发现 helper 返回顺序误用，经同任务修正和逐值复核后通过，不能把产物文件检查等同于统计正确性保证。LingSight 主站 React/FastAPI 已完成首轮本机工作区接入，真实账号验证了任务创建、澄清等待、刷新和取消；见[工作区验收记录](evidence/agent-workspace/README.md)。旧 `/qa` 仍保留，完整科研闭环联验与正式发布仍属于后续迁移。

以下保留原始产品讨论和已实现界面说明。涉及自建 Text-to-SQL 的目标已被上面的新方向和 ADR-0009 取代；原代码目前仍在仓库及运行镜像中。

## 核心目标
基于动物实验视频提供自动场景感知、鼠体 Mask/头尾 Pose、Tracking、可回溯行为指标，以及 SQL + 文献双知识源科研 Agent。

## 交付边界
- 第一范式：Morris 水迷宫。
- UI/基座：FastAPI 官方 full-stack-fastapi-template（MIT，React 前端），数据库适配为本机 MySQL（权威实验库 water_maze，见 ADR-0002 与 docs/08 Schema 审查）。
- Agent：一期使用云端 API；单主 Agent 通过 typed Tool 调用 SQL、统计、科研 RAG。
- 隐藏平台不可见时需元数据/校准输入，不能生成猜测坐标。
- 首次出现、首次入水、碰台、有效上台等事件分别定义并评测。

### 页面说明与操作流程

以下文字可用于产品说明书。主要页面与交互沿用已确认设计；异常状态为配套设计要求，尚未形成独立效果图。

**实验与视频管理。** 用户以实验为上下文集中管理视频，通过实验组、鼠号、训练日和处理状态定位记录。页面展示视频总数、待确认项与已完成项，并提供批量导入入口。待确认视频进入分析准备页，分析中的视频可查看进度，已完成视频进入单次分析结果页。列表中的动物信息同时包含实验组和鼠号，避免跨组鼠号混淆。首次进入且没有视频时，展示导入引导；导入失败时保留成功项，并明确失败文件及重试入口。

**分析准备。** 页面以视频画面为主体，右侧集中呈现自动识别结果、基准平台来源和起始帧候选。用户可在画面中调整水池与标志物，核对来自参考图或实验标定的基准平台，并通过时间轴与逐帧操作复核首次入水候选。坐标等精细参数默认收起；主要操作为“确认并开始分析”，辅助操作为“保存，稍后继续”。自动识别失败或结果不完整时，应保留可用结果，标出需要补充的项目，并提供重新识别或人工修正入口，不显示虚假的已确认状态。首次入水候选用于分析准备，不自动替代逃逸潜伏期的计时起点；不同事件仍按各自定义记录。

**单次分析结果。** 页面将原视频、轨迹叠加与关键事件定位放在同一工作区，右侧展示本试次指标、单位和计算口径，底部提供轨迹分布、空间热图和速度变化。用户可切换显示图层、定位事件帧、进入结果复核并导出数据或报告。厘米及厘米每秒等物理单位必须有有效空间校准支持；缺少校准或事件依据时，相关指标应显示不可计算及原因，不能填入零值或示例数值。推理完成与结果已复核分别展示，不能将计算完成直接视为科研质量已通过。

**实验统计与报告。** 用户按实验阶段、指标、训练日和实验组选择分析范围，查看学习曲线、组间分布及统计明细。页面显式说明统计单位、试次到动物的汇总方式、误差线含义及纳入范围，并可回查纳入试次。效果图示例先汇总同一动物当天试次，再计算组均值，以动物而非视频数作为组间样本单位。用户选择实验信息、统计口径、图表和明细数据后预览或导出报告。筛选后没有可用数据时展示空结果与筛选条件；缺失数据不以零值补齐。描述性图表不自动附加显著性结论。

## Text-to-SQL 设计
**输入**：实验 ID、自然语言、用户身份。
**步骤**：权限与意图识别 → 相关 Schema / 指标术语检索 → 查询计划 → LLM SQL → SQLGlot AST 校验 → 只读 MySQL 限时执行 → 数据粒度/空值检查 → 可复现的统计解释。
**领域语义层**：experiment、animal、group、trial、training_day、frame、metric；按真实数据库核实字段后才固定 Schema。必须定义“逐鼠-逐日-逐组”聚合口径。
**安全**：服务端账户只读；可查询视图/列白名单；LIMIT/执行超时/资源限额；脱敏、租户实验权限和审计。
**失败**：错误分型、有限次 SQL Repair，超过限制明确报告错误，不让模型编造结果。
**验收**：20–30 条真实科研 QA，与人工审核 SQL 和数值比对；另测越权、不可执行 SQL、错误统计粒度。

## 科研 RAG 设计
以 RAGFlow 为候选独立服务；测试真实论文 PDF 与实验手册，比较文档解析、标题/表格结构、Chunk、Metadata、BM25+Dense、RRF+Reranker；简单检索直接回复，多跳/证据不足时由 Agent 限定次数重检索并验证文献引用。
数据与文献分开：MySQL 存实验观测，RAG 索引存解释性知识；LLM 不能替代 Python 统计。
**验收**：Recall@K/MRR，文献引用支持率，证据不足拒答准确性，任务耗时和成本。

## CV 与推理
专用分割/关键点模型 + Tracking，输出 frame_id、mask/pose、置信度、轨迹、场景/模型版本。GPU Worker 与 API 解耦；任务支持明确状态与去重。评估 IoU/PCK、事件帧误差、端到端免手工操作比例。

2026-11-10 接入访谈已确认：本轮先完成单个水迷宫视频的真实推理与人工核对，科研 Agent 统计及报告留待后续贯通。流程为选择或导入视频 → 自动生成起始位置、水池和标志物候选 → 人工确认或修正 → 逐帧追踪 → 查看真实叠加结果与轨迹并人工核对。预标注确认与追踪结果核对分别记录，模型不能推断不可见的隐藏平台位置。

### 推理接入工程方案与现状

- **边界**：LingSight 后端鉴权后转发受限操作；独立推理服务管理视频目录、预标注、任务、产物和模型信息。浏览器只持有服务生成的视频标识，目录白名单和路径归属在服务端校验；原始视频只读。
- **阶段**：选视频 → 预标注排队及运行 → 等待人工确认或补齐 → mask 追踪 → v9 关键点 → 叠加视频 → 结果核对。页面分别显示等待、运行、失败、取消和完成；缺 mask 的帧、无效关键点及对应原因要保留，不能伪造轨迹。
- **保存**：使用目标机器用户可写本地目录的 SQLite 持久保存任务状态和每次运行的独立产物，单 worker 消费持久队列；由输入引用、标注快照、模型完整哈希、参数和运行记录追溯结果。状态的事务性、服务重启恢复、取消与产物发布的竞争边界需要测试，不依赖浏览器在线或进程内队列。
- **异常**：权重缺失或校验不一致、视频不可读、环境依赖缺失、预标注质量不足、计算失败和 overlay 失败均应给出明确阶段与原因；不悄悄换用 v8 或另一个 mark 模型。支持重试失败阶段，旧版本和已确认候选保留。缺平台仅限制平台相关事件与指标。
- **验收**：先做不含真实数据的契约与状态测试，包括目录边界、人工门禁、取消、重启恢复、阶段重试、版本绑定和缺平台；再使用一条真实视频验收上述端到端功能，并由研究人员核对结果。代码、模型和场景验证分别记录，不以一次跑通推断模型跨场景准确率。

### PA-T3 持久请求与安全恢复（#78，隔离工程）

新工作区创建、追问、恢复与澄清携带持久 UUID 请求标识；网关校验/保留，独立 Agent 将接收回执与业务变更原子提交，同标识异意图返回409。未确认请求跨页面刷新复用标识，不把断线当作取消；进度按当前用户/任务缓存的事件游标补齐。Pi Durable 从官方已保存 submission 继续同一 Run/会话，恢复前重新核验授权、版本和来源；仅明确分类的安全工具可重放，未知副作用保持中断并披露，不承诺普遍 exactly-once。新的请求/恢复能力缺失时禁用新执行，历史读取和停止保留。此为合成、多进程故障注入验证的源码能力，不是现役升级、真实科研或部署验收。


### PA-T5：受控文件与 Python（隔离实现，非现役部署）

现有工作区可选择明确授权的 ≤64 KiB UTF-8 CSV/JSON/TXT/MD 小材料。Agent 私有保存并返回 owner/environment 约束的 UUID 引用；创建任务只提交 `input_ids`，不接收宿主路径。原始字节与来源哈希保持不可变，后续修改创建新 Run 和输出版本。无数据库范围的任务只能处理明确提供的材料，不因此获得实验库权限；文件内容也不构成动物映射或科研结论确认。

`controlled-files-v1` 与既有 Durable/persistent requests/safe recovery 能力共同门控。受控 Python 复用 Agent 分析镜像，关闭网络、只读原文/根文件系统，只允许受限 tmpfs 计算输出，经整组校验与原子目录登记后形成表格、真实 PNG/SVG、代码、依赖记录、报告、来源和 ZIP。失败、超限、取消或未完成材料不能代替成功交付；工作区显示所属执行状态、哈希、预览和下载。新追问及丢失接收确认重试保留原引用与请求标识。

本切片在临时服务/真实 Harness、受控本地 HTTP 模型、真实 Docker、临时 MySQL/JWT 网关及实际工作区下载链路验证；不代表真实模型语义质量、科研验收或现役迁移/部署通过。Python/文件仍无通用安全重放承诺，与 PA-T3 的不安全操作恢复阻断契约对齐，通用副作用状态机留 PA-T4。
