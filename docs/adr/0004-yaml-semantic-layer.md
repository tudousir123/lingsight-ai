# 语义层采用自建轻量 YAML，配合 MySQL 只读视图白名单

2026-10-12 第 2 轮确认：用轻量 YAML 定义语义层（表/列业务含义、关系、同义词、聚合口径），作为 SQL 生成上下文与校验白名单的**唯一事实来源**；数据库侧同步建只读视图白名单作为权限边界。借鉴 WrenAI 的 MDL（其语义层定义格式）思想，不引入其运行时（承 ADR-0001）。

> 2026-10-13 措辞修订：删去原标题中的自造词「MDL-lite」——GLOSSARY 约定 MDL 是 WrenAI 的实现词汇，本项目一律称「语义层」；决策内容不变。

## Considered Options

- **表注释/视图注释承载语义**：零新增文件，但表达不了同义词、口径与关系，无法版本化审查。
- **部署 WrenAI 语义层**：能力完整，但等于引入整套平台（ADR-0001 已排除）。

## Consequences

- 真实库的命名陷阱必须在 YAML 中显式纠正口径，不能照搬 DDL：`animal_code` 实为「组-鼠-试次」编码而非动物标识；`session_label` 训练期=「第N次」、探测期=「第N象限」一列两义（见 docs/08 验证结论）。
- M1 的 Schema Linking 采用白名单核心表全量直塞提示词（同轮 Q4 决策），YAML 结构预留向检索式扩展的空间。
- 表/列校验白名单从 YAML 生成，与 SQLGlot AST 校验联动；权限错误的处置遵守第 2 轮 Q6 规则（不自动放宽限制）。
