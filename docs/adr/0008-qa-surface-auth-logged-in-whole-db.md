# 科研问答面 v1 权限：登录用户全库只读，不套实验授权

2026-10-14 用户决策（科研问答前端页 grilling Q2）：Text-to-SQL 的前端问答面在 v1 维持「登录即可查询全库」，不套用试次浏览面的显式实验授权模型。

## 背景：两个面权限不一致

- **试次浏览面**（实验/试次列表与详情，工单 #19–#23）：普通用户仅见被显式授权的实验，管理员可见全部；授权存应用库。
- **问答面**（`POST /api/v1/research/query`，M1-T4）：任何登录用户可问全库问题。库层防线 = `lingsight_ro` 只读账户白名单（5 表 + 视图）、单条 SELECT、强制 LIMIT/行数上限/超时、AST 校验、审计日志。

不一致是有意识的取舍，不是遗漏：前端按实验过滤只是装饰性安全，真正的实验级 ACL 必须下沉到 SQL 生成/执行层（把授权实验注入提示词与校验），是一个独立的后端工程。

## 决策理由

- M1 工单 #1 已明确将「多租户实验 ACL 细化」划出范围；当前用户规模（单课题组）下全库只读可接受。
- 数据库账户层已物理挡住：备份表（双计数源）、写操作、跨库、巨型列、未暴露表。
- 问答面与浏览面受众相同（本课题组科研人员），无外部多租户压力。

## 后果与触发条件

- 前端问答页不按实验授权过滤，也不展示「仅授权实验」类提示；页面如实展示数据来源。
- 引入第二个课题组/外部用户之前，必须升级问答面 ACL（生成时注入授权实验约束 + 校验层强制），届时反转本决策。
- 浏览面授权模型不受影响，继续收紧。
