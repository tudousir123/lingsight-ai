# PA-T3 durable admission and recovery Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Preserve one accepted intent and recover the same business Run and official Durable submission after process failure without unsafe tool replay.

**Architecture:** Agent owns transactional request receipts and business state. Official Durable SQLite owns execution checkpoints and conversation-scoped submission deduplication; the adapter reacquires those records, reconstructs QA evidence, and refuses unknown tool intent before enabling scheduling. Platform forwards request IDs and the workspace retains unacknowledged intents across reloads; event replay remains cursor-based and never cancels execution.

**Tech Stack:** Node 24/TypeScript, SQLite, Pi Durable 1.5.2, FastAPI/Pydantic, React, Playwright.
