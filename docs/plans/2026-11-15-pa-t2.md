# PA-T2 Pi Durable execution Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Execute synthetic research requests through real Pi Durable and preserve business Run completion, authorization, provenance and fail-closed workspace controls.

**Architecture:** Keep Agent's Engine/Worker and service-owned Task/Run/Artifact API authoritative. Share existing controlled research tools and completion policy with an explicit Durable session adapter; persist Run→execution→conversation/submission association separately from SDK session files. Platform only forwards/validates capabilities and renders service state. No recovery deduplication or external-effect state machine is claimed in this ticket.

**Tech Stack:** Node 24, TypeScript, pi-coding-agent 1.5.0 compatibility baseline, pi-durable 1.5.2 with pinned pi-ai/chord, SQLite, FastAPI, React, Playwright.

Temporary stores/configuration only; no global model credentials/default provider; no real data/cloud/deployment. No SelectWorktree tool is available: all operations use absolute assigned worktree paths.

## Verified implementation finding

The installed SDK 1.5.0 / pi-ai 1.5.2 combination failed real TypeScript branded transcript/stream compatibility. Rather than cast incompatible interfaces, all direct Pi packages were explicitly pinned to 1.5.2. Production ModelRuntime→controlled loopback SSE→real Harness and legacy SDK/container regressions verify the selected combination. Additional public ExecutionDriver authorization test is necessary because HTTP API offers no pause after a successful tool result but before the next provider send. No private scheduler internals are tested.
